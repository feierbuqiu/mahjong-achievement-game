# Internal version and evidence glossary

Internal `Vn` names identify research interfaces or experiment families.
They are **not semantic software versions, proof-strength rankings or
percentages complete**. A newer number can describe a stopped alternative.
Use the exact source hash, run identity and claim scope alongside a label.

| Label | Meaning in this repository | Evidence / boundary |
| --- | --- | --- |

| `evidence-v17-native-20261019` | Saved-record asset publication tag | Separate from semantic software versions; distributes the full native ledger graph |
| September concrete-proof package | Eight indexed nonempty roots and 1,008 Lean source modules | [Formal archive](../formal/README.md); not the actual empty-root theorem |

| V13 / V14 module suffixes | Row scheduling, compact hot-row and borrowed-plan components | Mathematical dependencies inherited by V16/V17; labels describe component lineage |

Counts of source files, imported modules reported by `leanchecker`, theorem
declarations, accepted rows and distinct original-game roots have different
scopes. For example, the V17 public source map contains 148 source files,
its replay entry reaches 146 source files, and the historical fresh checker
reports 145 imported modules. Do not add unlike counts or deduce novel-root
totals across overlapping proof packages.

Chronological snapshots retain old forecasts and holds as evidence. Use
[current status](PROJECT_STATUS.md) to resolve their present meaning and
[claim boundaries](CLAIMS.md) to choose wording for an external report.

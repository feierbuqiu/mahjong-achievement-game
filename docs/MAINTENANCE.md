# Maintenance after v2.0.0

The research snapshot and paper bodies are frozen by the signed release.
Contributions with new evidence, independent replication, clearer arguments
or necessary corrections remain welcome. No date is promised for an actual
empty-position kernel proof or further computation.

The following are future audited changes, not changes to the historical run:

- Make production refuse a bucket when the native close flag is absent or
  false, with a controller acceptance-gate regression test.
- Emit content hashes for bytes actually read in both source and target roles,
  or use independently hashed target copies. The historical declared-identity
  graph does not supply this observation.
- Bind one concrete input family through the final typed `finishWhole` route,
  then construct, save and cold-replay the actual opening declaration.
- Complete game-specific SAFE/target-address premises and join the numerical
  and game proofs; do not count numerical coordinates as certified game states.
- Audit and format a new operations revision; declare and validate runtime
  dependencies including `psutil`, rather than guessing the version used by an
  older run. The published dependency receipts describe their own packages.
- Address the latent missing return in the renamed historical C++ `main` and
  cosmetic/unused-source issues in a new reviewed revision, preserving the
  frozen source-to-run relation.
- Add primary-source bibliographic errata where warranted, outside the frozen
  papers, and validate an independent physical-machine reproduction.

Publication maintenance must not start Lean/native/GPU/WSL/full-table jobs or
schedulers. A new computational campaign requires explicit authorization,
its own budgets, input identities, source version and completed-outcome records.
